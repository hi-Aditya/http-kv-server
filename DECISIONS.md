# Decisions

**ADR-1: Fresh start in this repo.** The original MySQL-backed prototype (httplib + MariaDB + `std::list`/`unordered_map` LRU under one mutex) is replaced entirely; none of it fits the shared-nothing, WAL-based design. It remains in git history (`47a2e8c`).

**ADR-2: Level-triggered epoll.** Backpressure works by removing EPOLLIN while a connection's output is backed up or it is winding down; level-triggered makes that a one-line interest change, whereas edge-triggered needs per-socket "still has unread data" bookkeeping to avoid lost wake-ups. One `recv` per ready connection per iteration bounds per-wakeup work. Revisit only if profiling shows `epoll_ctl`/wake-up overhead matters.

**ADR-3: Bounded buffers instead of queues.** Per connection: read buffer <= 8 KiB + 1 MiB (the largest request the parser accepts), write buffer <= 256 KiB high-water mark + one response. Above the mark no further pipelined requests are parsed and EPOLLIN is dropped, so TCP flow control pushes back on the client. Connections beyond `--max-conns` get 503 and are closed; connections making no read/write progress for `--idle-ms` are closed.

**ADR-4: Chained table + CLOCK over buckets.** Entries are individually malloc'd, intrusively chained (32 B header, 8 B/bucket). Chaining over open addressing because there are no tombstones or backward-shift on removal (eviction and TTL remove entries constantly), and it degrades gracefully when the table cannot grow under the cap (longer chains, still correct). CLOCK over LRU: a hit only sets one byte (no list surgery, no 16 B/entry of list pointers). The hand walks buckets, clearing reference bits and evicting the first entry with a clear bit; two laps always find a victim. New entries start with the bit clear (an insert is not an access), which makes a one-pass flood evict itself rather than the hot set. Eviction is approximate by design: it follows hash order, not recency order.

**ADR-5: What the memory cap counts.** `--mem-mb` caps entries (modelled as the glibc malloc chunk size: header + key + value + 8 B, rounded to 16) plus the bucket array; `used <= cap` is an invariant checked after every operation in tests. It does not count connection buffers (<= ~2.3 MiB worst case each), the binary, or allocator fragmentation. Measured on the dev sandbox: uniform 1 KiB values give RSS ~ cap + 4 MB; adversarial 16 B-1 MiB size churn gave ~2.2x cap. The stated, tested bound is RSS <= 2x cap + 12 MB; size-class slabs or periodic `malloc_trim` would tighten it but are not justified without a measurement showing the need. A fixed `M_MMAP_THRESHOLD` (128 KiB) keeps large values out of the brk heap. The bucket array is capped at a quarter of the limit and grows only if old + new arrays fit, so a hard cap is never exceeded even transiently. Rehash is stop-the-world (relink only); it is a latency spike proportional to entries per shard, and tables never shrink.

**ADR-6: TTL semantics and clock.** `PUT /kv/<key>?ttl=<seconds>` (1 s to 10 years; anything else is 400). An overwrite without `ttl` clears any previous TTL (Redis `SET` behaviour). Expiry is lazy (on access, put, delete, and when the CLOCK hand passes) plus an active sweep of at most 1024 buckets per 10 ms, skipped entirely when no entry has a TTL. Times are unix milliseconds, not a monotonic clock, because the WAL (M4) must replay absolute expiry times across restarts; the sweep cadence uses the monotonic clock so a wall-clock jump cannot stall it. A backward clock jump delays expiry; a forward jump expires early. The store never reads a clock: callers pass `now`, so tests are deterministic.
